# Correction du passage évaluation → entraînement en précision mixte

- **Date :** 2026-09-11
- **Statut :** draft — correction vérifiée sur GPU v19 ; recharge finale vérifiée en v20
- **Question :** le pilote peut-il évaluer la base puis effectuer des mises à jour LoRA sans corrompre le contrat numérique AMP ?
- **Environnement :** worktree `complete-poc-evaluation`, notebook Kaggle privé v19, T4 gratuite, pile et artefacts figés dans le [manifest v19](SFT_V2_PILOT_V19_LAUNCH_2026-09-11.json).

## Cause localisée

Dans le trainer généré par v18, `UnslothSFTTrainer.py` lignes 1689–1703 active `args.fp16_full_eval` à partir de `args.fp16`, même quand les deux options de full-eval étaient initialement fausses. Le code de génération de la distribution Unsloth 2026.8.22 confirme ce comportement dans `unsloth/models/rl.py`.

Dans [Transformers 5.5.0, `trainer.py`](https://github.com/huggingface/transformers/blob/v5.5.0/src/transformers/trainer.py), lignes 2653–2657, une évaluation hors de `train()` applique alors `model.to(dtype=torch.float16, ...)`. Les paramètres entraînables peuvent ainsi perdre leur stockage FP32. La trace v18 échoue ensuite dans `GradScaler._unscale_grads_`, qui refuse les gradients FP16 dans ce chemin.

## Modification

Le runner remet `fp16_full_eval` et `bf16_full_eval` à `False` **après** la construction du trainer. Il conserve la précision mixte d'entraînement et la base quantifiée. Des assertions vérifient les types des paramètres entraînables avant/après loss, génération et entraînement.

La version 19 ajoute un contrôle GPU préalable :

1. Deux étapes d'entraînement et sauvegarde complète.
2. Nouveau processus, nouveau chargement de base et adaptateur sauvegardé ; générations greedy identiques exigées.
3. Reprise via `trainer.train(resume_from_checkpoint=...)`, contrôle des étapes restaurées dans l'optimiseur, poursuite jusqu'à quatre étapes.
4. Pilote depuis la base seulement si les deux processus terminent leurs contrôles.

Les évaluations du smoke portent sur deux références et deux générations. Elles ne sont pas la comparaison de qualité du pilote, qui conserve les 479 références et les 30 générations figées. Les paramètres de budget effectif, de mode et de reprise sont consignés dans chaque `summary.json`.
